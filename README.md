# 다시가게 RE:STORE

폐업 예정 소상공인의 집기·설비가 예비 창업자와 다른 소상공인에게 이어질 가능성을 보여주는 공모전용 웹 프로토타입입니다. 모든 자산·거래·지표는 가상 시연 데이터이며 실제 거래 실적이나 검증된 정책 효과가 아닙니다.

## 프로젝트 배경

폐업 과정의 남은 자산을 회수할 기회와 창업 초기의 설비 부담 완화 가능성을 함께 살펴봅니다. 지역 내 자원순환, 지원기관 연계와 정책 효과 측정을 제안하며 실제 기관 참여나 협약을 전제하지 않습니다.

## 주요 기능과 사용자 흐름

1. `/sell/new`: 사진을 선택하거나 건너뛰고 가상 자산을 3단계로 등록합니다.
2. `/market`, `/market/[id]`: 시연 자산을 검색·필터링하고 상세와 관심 표시를 확인합니다.
3. `/match`: 카테고리와 세부 품목·예산·지역·인수일에 따른 규칙 기반 추천을 확인합니다. 품목이 다르거나 품목을 모르는 자산은 정확 일치 추천에서 제외되며 점수는 성공 확률이 아닙니다.
4. `/market/[id]`: 금액과 비용을 입력해 실제 결제 없이 가상 완료를 체험합니다.
5. `/impact`: 이 브라우저의 가상 집계와 별도의 가정 기반 시뮬레이터를 확인합니다.
6. `/policy`: 정책 목적, 기관 역할 제안과 실증·사업화 전제를 살펴봅니다.

각 화면 상단의 **공모전 시연 안내**에서 순서와 빠른 이동을 확인하고 시연 데이터를 초기화할 수 있습니다. 초기화에는 확인이 필요하며 이 브라우저의 사용자 등록·관심·수요·가상 거래를 모두 삭제합니다.

## 기술 스택 및 구조

Next.js 16 App Router, React, TypeScript, Tailwind CSS, Lucide React, 브라우저 localStorage를 사용합니다. 시연 장비 그림은 외부 이미지 대신 코드로 직접 만든 SVG이며, 사용자가 사진을 등록하지 않으면 그림 또는 아이콘으로 표시합니다. 선택형 개발용 AI 분석에는 서버 Route Handler와 OpenAI Responses HTTP API, 이미지 검증에 sharp를 사용합니다.

```text
app/                  화면 및 서버 API 라우트
components/           공통 UI, 등록·마켓·매칭·시뮬레이션·대시보드
lib/domain/           데이터 모델과 검증
lib/repositories/     localStorage 접근 경계
lib/state/            클라이언트 공유 상태
lib/matching/         규칙 기반 추천 순수 함수
lib/simulation/       가상 거래 집계와 가정 계산
lib/registration/     등록 검증과 브라우저 이미지 압축
lib/ai/               선택적 서버 이미지 분석
lib/data/             가상 시드 데이터
tests/                단위 및 Playwright 브라우저 테스트
docs/                 제품·기술·시연 문서
```

## 로컬 실행

Node.js 24에서 검증했습니다. 프로젝트 디렉터리에서 실행합니다.

```bash
npm ci
npm run dev
```

기본 주소는 `http://localhost:3000`입니다. 원격 Jupyter 환경은 인증된 포트 프록시와 별도 경로 설정이 필요합니다.

## 환경변수

일반 수동 시연에는 API 키나 환경변수가 필요하지 않습니다. 자산·수요·거래·관심 정보는 `restore-demo-v2` localStorage 키에 저장됩니다. 첫 방문과 초기화 시 가상 데이터의 처분·인수 날짜는 현재 현지 날짜를 기준으로 다시 만듭니다. [.env.example](.env.example)은 빈 예시이며 실제 값은 Git에 포함하지 않는 `.env.local`에만 둡니다.

| 변수 | 용도 |
| --- | --- |
| `ENABLE_AI_ANALYSIS` | 개발 환경에서만 `true`로 선택적 분석 활성화. 기본 비활성화 |
| `OPENAI_API_KEY` | 개발용 서버 측 API 키. 클라이언트에 공개하지 않음 |
| `OPENAI_VISION_MODEL` | 이미지 입력과 Structured Outputs를 지원하고 해당 계정에서 이용 가능한 모델 |
| `NEXT_BASE_PATH` | 선택적 프록시 경로. 일반 Vercel 루트 배포에는 설정하지 않음 |
| `NEXT_DEV_ORIGIN` | 선택적 개발 프록시 호스트명. 프로덕션 동작에 필요하지 않음 |

AI 분석은 개발 환경에서 키·모델·활성화 변수가 모두 있을 때만 노출되며, 사진을 외부 OpenAI 서비스로 전송합니다. 제안을 검토·수정한 뒤 적용합니다. 인증과 분산 호출 제한이 없으므로 **프로덕션 및 Vercel에서는 활성화 값을 설정해도 버튼 대신 비활성 안내를 표시하고 서버가 AI 호출을 거부**합니다. 수동 등록은 계속 동작합니다.

## 테스트

```bash
npm run lint
npx tsc --noEmit
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E는 프로덕션 빌드 후 독립 브라우저와 3100 포트를 사용합니다. Linux에서 Playwright 브라우저 실행에 필요한 시스템 라이브러리와 한글 글꼴이 필요합니다. 외부 AI는 모의 응답 및 기본 비활성화로 검증합니다.

## Vercel 배포 방법 — 실행 전 사용자 승인 필요

Vercel 프로젝트는 `goyoomin/RESTORE` GitHub 저장소의 `main` 브랜치와 연결되어 있습니다. `main`에 새 커밋을 푸시하면 프로덕션 배포가 자동으로 시작됩니다. 로컬에서 확인할 때는 `npm run build` 후 `npx vercel deploy --prod`를 사용합니다. 루트 배포에서는 `NEXT_BASE_PATH`를 비워 둡니다. 수동 시연에는 AI 키가 필요하지 않으며, 비밀 값은 `.env.local` 또는 Vercel 서버 측 환경변수에만 보관합니다.

## 시연 데이터와 기능적 한계

시드 자산은 가상 사례이며 가격은 실제 시세가 아닙니다. 사용자가 등록한 정보와 가상 거래·관심·수요는 브라우저 localStorage에만 저장되므로 다른 브라우저나 기기와 공유되지 않고 삭제·변조될 수 있습니다. 기존 `restore-demo-v1` 데이터는 `restore-demo-v2`로 옮기며 자산·이미지·거래 기록은 유지합니다. 품목을 알 수 없는 레거시 자산은 상세 화면에서 세부 품목만 보완할 수 있고, 입력 전까지 매칭에서 제외됩니다. 기존 저장 자산의 지난 처분일은 유지해 만료로 표시하고, 초기화 시에는 날짜가 새로 생성됩니다. 실제 개인정보나 자산 정보를 입력하지 마세요.

실제 결제, 채팅, 계약, 본인 인증, 회원가입, 자동 대출·보증 심사는 구현하지 않았습니다. 선택적 AI 분석은 배포 환경에서 차단됩니다. 효과는 입력된 가상 값에 따른 계산이며 실제 성과나 예측이 아닙니다.

## 향후 확장
