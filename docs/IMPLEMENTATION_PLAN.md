# 단계별 구현 계획

현재 단계는 설계와 문서 작성까지다. 아래 항목은 후속 작업 제안이며 이번 단계에서 실행하지 않는다.

## 0. 설계
- [x] 작업 디렉터리와 기존 설정 확인
- [x] 제품 범위, 데이터 신뢰성 원칙, 기술 구조 및 구현 계획 문서화
- [ ] 설계 검토 후 다음 단계 착수

## 1. 프로젝트 기반
- [x] 기존 상태를 다시 확인하고 호환 버전으로 Next.js App Router·TypeScript·Tailwind CSS·Lucide React 구성
- [x] 공통 레이아웃, 반응형 내비게이션, 접근 가능한 기본 UI와 시연 안내 구성
- [ ] 빌드 및 기본 실행 확인; Vercel 배포 호환성 점검

## 2. 데이터와 도메인
- [x] 명시적으로 가상인 시드, 타입, 입력 검증, 버전 지정 저장소 인터페이스 및 localStorage 구현
- [x] 최초 시드 초기화, 기존 데이터 보존, 손상·저장 실패 처리
- [ ] 필터·규칙 기반 매칭·시뮬레이션·지표 계산을 순수 함수로 분리하고 경계 사례 검증

## 3. 폐업자와 창업자 흐름
- [x] 자산 등록 및 제한된 사진 선택, 유효성·오류·성공 상태
- [ ] 검색·지역·업종·예산 필터, 결과 없음과 상세 페이지
- [ ] 조건 입력, 점수 산식과 일치 사유를 보여주는 스마트 매칭
- [ ] 중복을 막는 거래 완료 시뮬레이션과 재방문 시 보존

## 4. 정책 설명과 평가
- [ ] 가상 시뮬레이션 건수·회수액·절감 추정치, 산식·누락 값·범위·한계 표시
- [ ] 기관 역할과 기존 정책 연계 및 시범사업을 제안으로 명시하고 실서비스 전제 설명
- [ ] 실제 제도나 링크가 필요하면 공식 출처 및 확인 시점 검증

## 5. 통합 검증 및 인계
- [ ] 등록 → 검색/매칭 → 상세 → 완료 → 대시보드 전체 흐름과 새로고침·직접 접근 확인
- [ ] 빈 상태, 잘못된 입력, 사진 오류, 저장 실패 및 누락 기준가 확인
- [ ] 모바일, 키보드, 스크린리더 레이블과 주요 버튼 동작 확인
- [ ] 적합한 테스트 및 프로덕션 빌드 실행, 배포 방법과 남은 위험 문서화

## 완료 기준
핵심 흐름이 한 브라우저에서 작동하고 모든 데이터·지표가 가상임을 구분할 수 있어야 한다. 추천은 규칙 기반이며 절감액은 가정에 따른 추정치로 표시한다. 실제 거래나 정책 성과를 주장하지 않고 제외 기능은 추가하지 않는다. Git commit과 push는 사용자가 별도로 요청하지 않는 한 수행하지 않는다.
