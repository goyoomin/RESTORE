# 다시가게(RE:STORE) 제품 명세

## 목적과 정책 가설

폐업 예정 소상공인이 집기·설비·장비의 회수 기회를 찾고, 예비 창업자와 다른 소상공인이 필요한 자산을 찾도록 연결하는 공모전용 프로토타입이다. 지역 자원순환, 폐업·재창업 지원 연계 및 정책 효과 측정 가능성을 제안한다. 자산 회수와 비용 절감은 검증할 정책 가설이며 이 프로토타입이 효과를 입증하지 않는다.

## 사용자

- **폐업 예정 소상공인:** 사진·품목·상태·가격·지역·처분일을 입력해 자산을 등록하고 가상 완료 흐름을 확인한다.
- **예비 창업자 및 소상공인:** 세부 품목, 예산, 경기도 시·군, 희망 일정을 입력하고 규칙 기반 추천과 가정된 비용 차이를 확인한다.
- **정책 담당자 및 심사위원:** 제안된 운영 시나리오, 역할·비용 산식, 가상 지표와 실증 설계를 확인한다.

## 화면과 기능

| 화면 | 주요 기능 |
| --- | --- |
| 메인 `/` | 정책 목적, 시연 안내와 등록·검색·매칭·대시보드·정책 소개 이동 |
| 자산 등록 `/sell/new` | 사진 선택과 세부 품목을 포함한 3단계 등록, localStorage 저장 |
| 장비 검색 `/market` | 자산명·카테고리·품목·설명 검색, 필터·정렬, 관심 표시 |
| 장비 상세 `/market/[id]` | 품목·지역·상태 확인, 이전 자산 품목 보완, 가상 거래 시뮬레이션 |
| 스마트 매칭 `/match` | 품목·예산·지역·인수일 입력, 규칙 점수·근거와 결과 없음 안내 |
| 정책 효과 `/impact` | 완료 시뮬레이션 집계와 별도 시범사업 가정 계산 |
| 정책 소개 `/policy` | 가상 운영 계획·기관 역할 제안·비용 산식·성과 측정 제안 |

모든 시연 데이터와 지표는 실제 거래·정책 성과가 아니다. 서비스는 회원가입·연락처 없이 체험하며 로딩, 저장 실패, 빈 목록, 없는 자산과 모바일·키보드 사용을 처리한다.

## 저장과 레거시 품목

현재 데이터 형식은 `schemaVersion: 2`, 저장 키는 `restore-demo-v2`다. 이전 `restore-demo-v1`은 기존 자산, 이미지, 거래, 관심과 수요를 유지해 이전한다. 이전 데이터에 없던 세부 품목은 추측해 넣지 않는다. 상세 화면에서 사용자가 해당 카테고리의 품목을 선택하면 자산의 세부 품목만 저장되며, 보완 전에는 정확 품목 매칭에서 제외된다. 사용자 입력은 이 브라우저 localStorage에만 저장되고 기기 간 공유나 서버 백업은 없다.

최초 시드에는 가상 자산 8건과 수요 3건이 있으며 처분·인수 날짜는 시드 생성일 기준 상대 날짜다. 초기화하면 날짜가 다시 생성된다. 기존 자산의 만료일은 자동 수정하지 않는다.

## 사용자 흐름

1. 폐업 예정자: 메인 → 사진·품목·정보 등록 → 마켓 상세 → 가상 거래 완료 → 대시보드 반영.
2. 창업자: 마켓 검색 또는 품목 조건 입력 → 추천 근거 확인 → 상세 → 거래 조건을 확인하는 가상 시뮬레이션.
3. 심사위원: 정책 소개에서 가정된 대상·지역·운영 단계·비용 산식을 보고 대시보드 지표 정의를 확인.

## 매칭 원칙

카테고리와 세부 품목이 정확히 일치해야 추천한다. 어느 쪽이든 품목이 없거나 서로 다르면 제외한다. 이후 예산·지역·인수 일정을 검증하고 품목 40점, 가격 15/20/25점, 지역 8/18/25점, 일정 5/7/10점으로 최대 100점을 계산한다. 점수는 조건 적합도이지 성공 확률이나 AI 결과가 아니다.

## 거래·효과 표시 원칙

- 완료 거래금액 합계는 거래 총액 및 비용 차감 전 판매자 자산 회수액이다.
- 판매자 순회수액은 거래금액에서 판매자 부담 비용을 뺀 값이다.
- 구매자 비용 차이는 입력한 비교 신품 가격에서 거래금액과 운송비를 차감한다. 설치·수리비 등은 제외하며 음수는 추가 지출 가능성으로, 기준가 누락은 추정 불가로 표시한다.
- 비교가격과 근거는 사용자 입력 시연 가정이며 실제 시세가 아니다. 거래는 `simulated: true`로만 기록한다.
- 판매자 회수액과 구매자 절감액을 합쳐 총 편익이라고 주장하지 않는다. 가정 계산기는 저장 거래와 분리한다.

## 정책 소개와 시범사업 구상

`/policy`는 경기도 내 1개 시·군, 6개월, 판매자 최대 50곳·구매자 최대 50명을 운영 규모를 생각해보기 위한 제안 시나리오로 표시한다. 지역·대상·예산·기관 참여는 확정되지 않았다. 모집·안내 → 자산·수요 확인 → 매칭 및 인수 조건 확인 → 동의 기반 결과·비용 조사 순서를 제시한다. 기관별 역할, 비용 항목과 산식, 실증 KPI는 제안이다. 기존 지원 정책은 최신 공식 자료와 담당 기관 확인 후 자발적 안내·의뢰 방식으로 연결하는 구상이며, 자동 자격 판정이나 보증·대출 승인을 뜻하지 않는다.

## 제외 범위 및 확장 전제

실제 결제, 채팅, 매매계약, 본인 인증, 복잡한 회원가입, 자동 대출·보증 심사는 구현하지 않는다. 실서비스 전에 인증·권한, 개인정보 최소 수집·보호, 소유권·상태·허위 자산 검증, 거래 안전·분쟁 처리, 서버 저장소·동시성 관리와 비교 기준이 있는 실증 평가가 필요하다.

## 선택형 이미지 분석

개발 환경에서 조건이 충족되면 서버 분석 제안을 이용할 수 있지만, 프로덕션·Vercel 배포에서는 보안과 비용 보호를 위해 화면과 API 모두 비활성화된다. 사진 없이 수동 등록은 계속 가능하다. 실제 운영에는 인증, 분산 호출 제한, 비용 한도와 개인정보 처리 검토가 선행되어야 한다.
