# 기술 및 데이터 설계

## 현재 상태와 범위
Next.js 16 App Router, React, TypeScript, Tailwind CSS와 Lucide React로 초기 화면을 구성했다. 자산 등록 폼, 데이터 모델, 브라우저 저장소와 읽기 전용 자산 목록·상세를 구현했다. 검색·필터·정렬, 관심 표시, 규칙 기반 매칭과 가상 거래 및 가상 지표를 구현했다. 기본 수동 시연에는 서버 DB나 API 키가 필요하지 않다.

## 예상 구조
```text
app/
  page.tsx
  sell/new/page.tsx
  market/page.tsx
  market/[id]/page.tsx
  match/page.tsx
  impact/page.tsx
  policy/page.tsx
  layout.tsx
  globals.css
components/       # 공통 레이아웃, 폼, 자산 카드, 상태 안내
lib/
  domain/         # 타입, 검증, 필터, 매칭, 지표 순수 함수
  data/           # 가상 시드 데이터
  repositories/   # 인터페이스와 localStorage 구현
  hooks/          # 클라이언트 데이터 로딩과 오류 상태
public/           # 사용 권한이 확인된 정적 시연 자산
```
서버 컴포넌트 중심으로 정적 화면을 구성하고 브라우저 저장소·폼·상호작용이 필요한 영역만 클라이언트 컴포넌트로 둔다. 렌더링 중 서버에서 `window`를 읽지 않고 마운트 후 로드해 로딩 상태를 표시한다. 동적 상세 경로는 클라이언트에서 로컬 ID를 조회하며 직접 접근과 새로고침, 없는 ID를 처리한다.

## 구현된 도메인 데이터
금액은 음수가 아닌 안전한 정수 원화, 모든 날짜는 유효한 `YYYY-MM-DD` 문자열이다. 실제 상세 주소와 개인정보는 저장하지 않는다.

- **Asset:** `id`, `title`, `category`, 선택적 `itemType`, `description`, `condition`, `askingPrice`, `region`, `district`(시·군), 선택적 `neighborhood`(읍·면·동 수준), `disposalDeadline`, `status`(`AVAILABLE`/`RESERVED`/`COMPLETED`), `image`, `createdAt`, `dataOrigin`(`seed`/`user`). 시드 이미지는 라이선스 외부 이미지 대신 품목별 Lucide 아이콘을 쓰며 등록 사진은 브라우저에서 압축한 data URL이다. 사진과 설명은 선택 사항이다.
- **BuyerNeed:** `id`, `category`, 선택적 `itemType`, `maxBudget`, `preferredRegion`, `preferredDistrict`, 선택적 `preferredNeighborhood`, `desiredPickupDate`, `createdAt`.
- **DemoTransaction:** `id`, `assetId`, 선택적 `buyerNeedId`, `transactionPrice`, `sellerCost`, `buyerShippingCost`, 선택적 `referenceNewPrice`와 `comparisonSource`, `completedAt`, 항상 `true`인 `simulated`. 실제 결제나 매매를 의미하지 않는다.
- **DemoStore:** `schemaVersion: 2`, `assets`, `buyerNeeds`, `transactions`, 선택적인 `favoriteIds`. 최초 시드는 가상 자산 8건과 수요 3건이며 거래 기록은 없다. 모든 가격은 임의의 시연 값이다. 새 시드와 초기화 시 처분·인수 날짜는 기준일로부터 생성하므로 시간이 지나도 데모 목록이 전부 만료되지 않는다.

## 저장소 경계와 오류
`DemoRepository` 인터페이스와 localStorage 구현이 읽기, 자산 추가·상태 변경, 수요 추가, 가상 거래 완료 및 초기화를 제공한다. 현재 `restore-demo-v2` 키를 사용하고, 기존 `restore-demo-v1` 데이터는 구조를 검증한 뒤 품목 유형을 추측하지 않은 채 v2로 옮긴다. 기존 키는 백업으로 보존한다. 사진·가상 완료 기록·즐겨찾기·사용자 자산과 만료일은 그대로 유지되며, 품목을 모르는 레거시 자산은 정확 품목 매칭에서 제외된다. 읽기와 쓰기 전에 형식·날짜·금액·중복 ID·거래 참조를 검증한다. 완료 기록과 자산 상태는 한 번에 저장한다. 손상된 데이터나 지원하지 않는 버전은 오류를 표시하고 자동 삭제하지 않으며, 사용자 확인 후에만 초기화한다. 저장 거부·용량 초과도 오류로 표시한다.

`DemoProvider`가 마운트 후 브라우저 저장소를 읽고 모든 클라이언트 화면에 동일한 상태를 제공한다. 최초 렌더링은 서버와 클라이언트 모두 로딩 상태여서 hydration 불일치를 피한다. 다른 탭의 `storage` 이벤트를 수신하며 쓰기 전에 저장소를 다시 읽지만, localStorage는 트랜잭션이나 탭 간 동시 쓰기 충돌 방지를 보장하지 않는다.

localStorage는 기기·브라우저별 저장소이며 보안 경계나 공유 데이터베이스가 아니다. 데이터는 삭제·변조될 수 있고 브라우저를 지우면 사라진다. 개인정보와 실제 거래 정보를 저장하지 않는다. 추후 DB 도입 시 서버 검증, 인증·권한, 트랜잭션, 동시성, 이미지 저장 및 마이그레이션을 별도 설계한다.

## 계산 규칙
- 검색은 키워드와 카테고리·지역·장비 상태·가격·거래 가능 상태를 결합한다. 처분 기한이 지난 미완료 자산은 거래 가능에서 제외하고 별도로 표시한다.
- 추천은 가용 상태·기한·카테고리와 세부 품목의 정확 일치·예산·인수일을 먼저 검증한다. 품목 정보가 없거나 다른 품목이면 추천에서 제외한다. 품목 적합성 40점, 가격 15/20/25점, 지역 8/18/25점, 일정 5/7/10점을 부여한다. 세부 지역 미입력 시 같은 시·군은 25점을 적용한다. 동점은 등록일 최신순, ID순이다. 점수는 규칙 기반이며 성공 확률이 아니다.
- 예상 절감액은 기준가가 있을 때 `기준가 - 시뮬레이션 가격 - 구매자 운송비`이다. 음수는 추가 지출 가능성으로 표시하며 설치·수리비는 제외한다. 기준가 누락은 0원이 아닌 추정 불가다.
- 대시보드는 완료 기록을 기준으로 건수와 시뮬레이션 가격 합계, 판매자 비용을 차감한 순회수액, 기준가가 있는 건의 예상 절감 합계를 산출한다. 추정 가능 건수와 불가 건수도 표시한다. 모든 지표는 가상이며 현재 브라우저 범위다.

## 검증 계획
도메인 순수 함수의 필터·점수·누락 기준가·중복 완료·집계 경계 사례를 검증한다. 브라우저에서 등록과 사진, 검색, 상세 직접 접근, 매칭, 완료 후 새로고침과 대시보드 반영, 데이터 손상·용량 초과와 빈 상태를 점검한다. 모바일·키보드 접근성, 빌드 및 배포 호환성도 확인한다. 실제 외부 연동이나 운영 성과는 검증 대상이 아니다.

## 자산 등록 사진
JPG·PNG·WebP 원본은 10MB 이하로 제한하고 브라우저 캔버스에서 최대 1200px, 350KiB 이하 JPEG로 압축한다. 서버 전송 없이 저장 객체에 포함한다. 저장 실패 시 폼을 유지하고 사용자가 사진을 삭제하거나 공간을 확보한 뒤 재시도할 수 있다. 브라우저의 저장 한도는 환경에 따라 다르므로 압축해도 저장을 보장하지 않는다.

관심 표시는 자산 ID 목록으로 브라우저에만 저장되며 판매자에게 전달하지 않는다. 상세 ID는 브라우저 저장소에서 확인하므로 존재하지 않는 ID는 클라이언트에서 안내하며 서버 HTTP 응답은 200일 수 있다. 텍스트에서 흔한 전화번호·이메일 패턴을 가리지만 임의의 개인정보나 이미지 속 정보를 완벽하게 식별하지 못하므로 등록 시 개인정보를 입력하지 않아야 한다.

가상 거래는 사용자가 확인한 후 기록과 자산 완료 상태를 한 번에 저장한다. 저장 직전 연결된 구매 조건의 품목 일치, 거래금액과 운송비 합계의 예산, 희망 인수일과 처분 기한, 등록 희망가, 완료·만료 상태, 중복 완료를 다시 검증한다. 날짜 비교는 YYYY-MM-DD로 수행하며 현재 날짜는 사용자 브라우저의 로컬 날짜다. localStorage는 탭 간 원자적 잠금을 제공하지 않아 동시 탭의 경합까지 완전히 방지하지 않는다.

정책 효과 대시보드는 완료 자산에 연결된 유효한 시뮬레이션 기록을 자산과 기록 ID 기준으로 중복 제거한다. 판매자 자산 회수액은 비용 차감 전 거래금액이며 거래 총액과 동일하므로 합산하지 않는다. 구매자 차액은 음수를 보존하고 비교가 불가능한 사례를 별도 집계한다. 등록→매칭→완료 화면의 매칭 단계는 저장된 수요 조건 건수이며 추천 노출이나 실제 성사 건수가 아니다. 별도 가정 시뮬레이터는 저장된 거래와 합산하지 않는다.

## 선택적 AI 사진 분석
`/api/assets/analyze`는 서버에서만 OpenAI Responses API에 사진을 전달한다. 기본값은 비활성이며 키·모델은 `.env.local`의 `OPENAI_API_KEY`, `OPENAI_VISION_MODEL`, `ENABLE_AI_ANALYSIS=true`로 개발 환경에서만 지정한다. 선택한 모델이 이미지 입력과 Structured Outputs를 지원하고 계정에서 사용 가능한지는 운영자가 확인해야 한다. SDK 없이 공식 HTTP API를 호출하며 `store: false`를 요청한다. 사진은 기존 등록 데이터의 localStorage 저장 외에 분석을 위해 서버 파일로 저장하지 않는다. OpenAI로의 전송과 외부 서비스의 데이터 처리 정책은 별도로 고려해야 한다.

서버는 JSON 크기와 이미지 형식·서명·디코딩·크기, 모델 출력 구조와 카테고리를 검증하고 제한 시간과 개발용 프로세스별 분당 3회 제한을 적용한다. 이 제한은 인스턴스 간 공유되지 않는다. 인증이나 신뢰할 수 있는 분산 제한이 없으므로 `NODE_ENV=production` 또는 Vercel 배포에서는 `ENABLE_AI_ANALYSIS=true`라도 서버가 분석을 거부한다. 공개 운영 전 인증, 분산 요청 제한, 비용 한도와 개인정보 보호 설계를 추가해야 한다. 실패 시 수동 등록은 계속 가능하다.
