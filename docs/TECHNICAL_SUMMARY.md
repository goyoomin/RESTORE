# 다시가게 기술 요약

## 전체 시스템 구조와 데이터 흐름

Next.js 16 App Router의 서버 페이지와 React 클라이언트 컴포넌트로 구성한다. `DemoProvider`는 클라이언트 첫 마운트 후 `DemoRepository`를 통해 `restore-demo-v2`를 읽고 자산·수요·시뮬레이션 상태를 공유한다. 저장 객체는 `schemaVersion: 2`다. localStorage가 비어 있으면 가상 시드 8개와 수요 3개를 만든다. 초기 날짜는 생성 기준일에서 상대적으로 계산하고 초기화 때 다시 만든다.

기존 `restore-demo-v1`은 유효성 검증 후 v2로 이전한다. 데이터·사용자 사진·완료 시뮬레이션·관심 목록을 보존하고 v1 백업을 남긴다. v1에 세부 품목이 없으면 임의 추정하지 않는다. 사용자는 자산 상세 화면에서 해당 카테고리의 세부 품목만 보완할 수 있으며 저장 시 자산의 나머지 속성과 거래 기록은 그대로 유지된다. v1 저장 공간 부족 시 원본은 삭제하지 않는다.

## 주요 모듈

- `components/asset-registration.tsx`: 이미지 선택·압축, 품목을 포함한 등록 정보 입력, 검증과 로컬 저장.
- `components/asset-image.tsx`: 자체 제작 장비 SVG, 업로드 사진 또는 Lucide 아이콘 폴백.
- `components/legacy-item-type-editor.tsx`: 구버전 미분류 자산의 품목만 보완.
- `components/demo-assets.tsx`, `asset-detail.tsx`: 검색·필터·상세·관심 표시.
- `components/smart-matching.tsx`, `lib/matching/match.ts`: 창업 수요 저장과 규칙 기반 점수 계산.
- `components/transaction-simulation.tsx`, `lib/simulation/transaction.ts`: 연결된 구매 조건 및 완료 검증.
- `components/impact-dashboard.tsx`, `lib/simulation/impact.ts`: 완료 기록의 비용 계산 및 저장 기록과 분리된 가정 계산.
- `app/policy/page.tsx`: 가정된 시범 운영 대상·지역·과정·역할·비용 산식·KPI 제안.

## 매칭 알고리즘

거래 가능한 상태, 처분 기한, 경기도 지역, 정확한 카테고리와 세부 품목, 예산 및 인수 일정을 선검증한다. 구버전처럼 품목이 없는 자산이나 수요, 품목이 다른 자산은 추천하지 않는다. 정확 일치 품목 40점, 가격 비율 15/20/25점, 지역 8/18/25점, 인수 일정 5/7/10점으로 합계 100점이다. 점수는 규칙 기반 조건 적합도이며 성공 확률이 아니다.

## 가상 거래의 저장 전 검증

완료 저장 시 자산이 거래 가능하고 기한이 지나지 않았는지, 거래금액이 0보다 크고 등록 희망가를 넘지 않는지 확인한다. `buyerNeedId`가 연결된 경우 해당 수요가 존재해야 하며 자산과 수요의 품목이 일치하고 거래금액+운송비가 구매 예산 이하이며 인수 희망일이 현재일과 처분 기한 사이인지 확인한다. 이미 완료된 자산 및 중복 기록은 거부한다. 확인된 기록만 `simulated: true`로 저장하고 자산 상태를 완료로 바꾼다.

## 정책 효과 계산

- 거래 총액·판매자 회수액 = 완료 시뮬레이션의 거래금액 합계
- 판매자 순회수액 = 거래금액 − 판매자 부담 비용
- 구매자 추정 차액 = 사용자가 입력한 비교 신품 가격 − 거래금액 − 구매자 운송비
- 비교 기준가가 없으면 추정 불가. 음수는 추가 지출 가능성으로 표시한다.

비교가격·출처는 사용자가 정한 시연 가정이며 실제 시세가 아니다. 설치·수리비는 계산에서 제외한다. 자산 회수액과 구매자 절감액을 총 편익으로 중복 합산하지 않는다. 시범사업 가정 계산기는 localStorage의 가상 거래 집계와 별도로 표시한다. 실제 사업 KPI는 실제 인수 증빙·비용 자료·설문 동의 등 실증 데이터로 측정해야 한다.

## 이미지와 AI

가상 상품 일러스트는 코드로 직접 만든 인라인 SVG이므로 외부 이미지 권리나 제3자 이미지 호스팅에 의존하지 않는다. 미지정·알 수 없는 이미지 식별자에는 기존 Lucide 아이콘을 표시한다. 사용자가 선택한 JPG·PNG·WebP는 브라우저에서 최대 크기와 용량을 줄여 data URL로 저장한다.

선택형 사진 분석은 `/api/assets/analyze`를 통해 서버에서만 호출한다. 개발 환경에 키·모델·활성화 값이 있을 때만 UI 버튼을 표시한다. Vercel 포함 배포 환경에서는 버튼 대신 비활성 사유를 알리고 API도 요청을 거부한다. 키는 클라이언트에 공개되지 않으며 수동 등록은 독립적으로 동작한다.

## 배포와 한계

Vercel 프로젝트는 GitHub `goyoomin/RESTORE`의 `main` 브랜치와 연결되어 있으며 새 푸시는 프로덕션 배포를 트리거한다. localStorage는 브라우저·기기별이고 데이터베이스, 보안 경계, 서버 백업, 탭 간 동시성 잠금이 아니다. 실서비스 전 인증, 개인정보 보호, 소유권·작동 상태 확인, 거래 안전·분쟁 대응, 데이터베이스·이미지 저장소 및 실증 평가 설계가 필요하다.
